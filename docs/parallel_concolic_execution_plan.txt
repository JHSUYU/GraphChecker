GraphChecker 并行 concolic 路径探索
===================================

状态：当前实现设计，2026-07-26。

目标
----

并行的是多个 custom-JDK 进程，不是在 HotSpot 内共享一个 concolic context。
每个 worker 独占：

    taskId
    JVM / ThreadContext
    Z3 query
    replay input
    raw result
    import result

custom-JDK 内部保持单 activation、单线程 symbolic context。这样既能使用服务器
多核，也不把 VM shadow state、path condition 或对象 identity 变成共享可变状态。

核心数据模型
------------

一个实际 region invocation 对应一个 RegionInstancePlan。它是稳定 envelope：

    regionInstanceId
    rootSelector
    inputActions
    branchObservations
    executionGoals[]

execution goal 是需求，不是新的 activation：

    OUTPUT_CLOSURE
        得到 requested OUT 在正常 region exit 时的最终 symbolic expression。

    TARGET_REACH
        得到 consumer target 的 reach condition。

Scheduler 将一个 goal 投影为 ExecutionTask：

    taskId
    goalId
    regionId
    regionInstanceId
    symbolize[]
    branches[]
    outputClosure
    replayContract (仅 replay task)

所有 worker 和产物都用 taskId。不存在用 activationId 承载 taskId 的兼容字段。

Output closure 路径探索
-----------------------

对于指定 OUT，静态阶段计算：

    inputs
    relevant branch sites
    methods
    capture at normal region exit
    causal edge ids

每次 replay 正常离开 region 时直接读取 OUT 的最终 symbolic expression。算法不选择
某个静态赋值点，也不关心翻转后最终执行的是哪个写点：

    path condition + OUT-at-exit expression

如果路径没有写字段，region-end 值自然仍是 pre-state expression，形成 frame
condition。多个写点、重复写点和分支后的最终写入都由 VM 执行语义自然决定。

Branch flip 只是枚举 output transformer 路径的内部手段：

    seed path
      -> 找到 output slice 中尚未探索的 branch occurrence
      -> 构造精确 ordered-prefix + opposite outcome query
      -> Z3
      -> concrete replay
      -> import path relation
      -> 产生下一批 frontier

只有 output slice 中的 branch 才能进入 worklist。与 OUT 无关的 symbolic branch 不会
成为候选。

并行 wave
---------

一个 wave 的输入是 coordinator 发布的 immutable snapshot：

    admitted summaries
    closed exploration records
    pending flip tasks

wave 内的 task 彼此独立，因此可以全部并行：

    wave N snapshot
      -> plan q1 ... qK
      -> K 个 worker 并行 solve/replay/import
      -> coordinator 等待全部 worker
      -> 只合入完整、可执行的结果
      -> 发布 wave N+1 snapshot

worker 不能写共享 ledger。coordinator 是下列 aggregate artifact 的唯一 writer。
任一 worker 失败时不发布部分 wave。

并行度
------

默认并行度使用可用 CPU 数：

    CONCOLIC_PATH_JOBS=$(nproc)

允许显式设置更高的值。实际并行数始终为：

    min(CONCOLIC_PATH_JOBS, current-wave pending task count)

因此把 40 提高到 64 只在一个 wave 确实有超过 40 个 task 时有效。不同 fixture 也可在
外层并行，但必须给每个 fixture 独立 work root。

Worker 生命周期
---------------

一个 SAT worker：

    1. 读取 singleton ExecutionTask 和 immutable observed plan。
    2. 用共享表达式语义生成 branch-flip SMT。
    3. 调用 Z3。
    4. 将 model 只写到任务声明的 materializable input。
    5. 启动一个 custom-JDK -Xint replay。
    6. 验证实际 branch event 的 site、occurrence、prefix 和 outcome。
    7. 导入 path condition 与 region-end output expression。
    8. 将完整 result 交给 coordinator。

UNSAT task 不启动 replay，也不制造 execution task 或 activation。

容器语义
--------

array、Map、List、Set、Queue/view 全部由 custom-JDK 的 activation-local shadow
container 产生 ContainerRelation expression DAG。Path solver 和 Composer 共用
ContainerSmtCodec：

    indexed:     state/read/write/size/append/insert/remove/clear
    associative: state/read/put/remove/contains/size/clear
    view:        entry/key/value view + iterator position

Java planner 不生成 element binding、Map snapshot、entry projection 或动态 field
binding。worker 只 materialize 静态 output slice 声明的真实 scalar input；容器操作
关系由 VM replay 重新观察。

确定性
------

queryKey 只取 canonical semantic payload：

    region instance
    goal
    output closure fingerprint
    ordered prefix
    flip site / occurrence / desired outcome

taskId 由 queryKey 派生。聚合时按 queryKey 排序并去重，因而 worker 完成顺序不会改变
worklist、merged summary 或最终 SMT。

失败诊断
--------

coordinator 必须打印 taskId、queryKey 和任务目录。重点产物：

    worklist manifest
    execution_tasks.jsonl
    task/query.smt2
    task/z3.out
    task/model_assignments.json
    task/raw_result.jsonl
    task/imported_summary.jsonl
    task/import_diagnostics.jsonl
    task/stderr.log

不要依赖重新引入大量 mirror boolean 或整份 JSON shape assertion。正确性门槛是：

    exact task identity
    executable materialization target
    exact ordered replay witness
    complete output closure
    empty semantic gaps
    expected final Z3 SAT/UNSAT

实现原则
--------

- 不过度设计：不做 distributed queue、共享 VM context、speculative cross-wave merge。
- 不过度验证：不在 shell、Importer、Composer 重复检查同一事实。
- 不静默降级：无法精确建模的操作直接产生一个明确 gap/abort。
- 不为兼容保留旧 schema：writer、reader、shell 同时原子切换。
- 性能优化不能改变 path identity、output closure 或 replay admission。
