## (d) Lessons and traps (non-obvious, with evidence)

1. **HBASE_RPC doors.**
   - The REQUEST door sits at AbstractRpcClient#callMethod, before RpcConnection#sendRequest; the RESPONSE door at RpcConnection#finishCall, before Call#setResponse.
   - The HOOK rows in experiments/hbase/doors.jsonl place them after CausynthRpc#sent and #parsed.
   - A placed door family is always in scope (ScopeGrowth --doors), so every client RPC of the workload gets REQUEST fault flips. In 10 that was 70 calls × 3 kinds, the whole replay budget (R17-10).
   - The backup bug's first witness (R4-bak) was a REQUEST fault producing plain contention, not the bug. It needed a one-acquirer workload (TestCausynthBackupLockReplyLost) and an expected mechanism naming RpcConnection.
2. **Reply-leg rule** (tree CausynthRpc#starting, 619c9836a6, kept).
   - A request made inside a reply's exchange stands on that reply. Without the rule, requestStarting ends the reply and the send has no context (MESSAGE_CONTEXT_REFUSED; the server then serves under a leftover context).
   - It still covers sends made straight from an RpcCallback: AsyncScanSingleRegionRpcRetryingCaller next()/call(), closeScanner(), renewLease().
   - Inside a continuation the inbound is set aside, so the rule never fires there. Dropping the rule (93ff0b8ff9) was reverted (0e1766e8ca) after review.
3. **Async continuation identity** (7384c1e61 + 28ec6763b).
   - The listener of a CompletableFuture runs inline on the registering thread when the reply came first, else later on the event loop inside the reply leg. Its request's anchor differed between passes (R9-11, OCCURRENCE_ANCHOR_UNMATCHED).
   - Fix: carrier wrappers (runtime/Continuations).
     - The claim is never run-here, so both orders share one schedule context.
     - It stands apart from the thread's running occurrence (an opaque region).
     - The inbound and request-in-hand are set aside.
     - The start is named `<site>:<first caller outside the registering class>` and counted per that name. Before this, FutureUtils#u3@44 was a test-wide count.
     - The registration writes no START event (R13 had 525 unclaimed STARTs).
   - Open (TODO HBase 7): VM activations, store-read rows and wire exports do not stand apart (review M3); a chain re-registered per poll nests one frame per poll (21).
4. **Timer lineage** (3015b1cb0). HBase retries on a shaded Netty HashedWheelTimer: `newTimeout` is a submission and `TimerTask.run(Timeout)` (one argument) is a work entry. Types match by suffix `*.netty.util.TimerTask`, any shading. The lineage scan of a test class family uses the root `<dir>#<class>` (26d252eb5).
5. **Procedure step hand-off inside the claim** (tree 464505d240).
   - CausynthStep filed the next step's START after the claimed run() had returned. The START then captured the worker's own context: its AbstractProcedureScheduler.poll WAKE root, or the request a lazily created worker had inherited.
   - Evidence: R10-31 had ~40 next-step hand-offs under Root:WAKE/...poll#k, and the dispatcher's ExecuteProcedures inherited them (65 BLOCKING). R16-10 had 855 events under WAKE poll roots; the first recording after the fix (R17-10) had 0.
   - Natively no step ever takes the unclaimed path (a diagnostic run counted 0); every runnable path goes through AbstractProcedureScheduler#push.
6. **Ledger starvation.** A planner head charges its whole -Xmx (21.5 GB) on one host, and the 70 % cap is 22.1 GB, so that host admits no replay. Two heads on a 3-host group left one replay host. R17-10 landed nothing for 50 min and R16-10's seed replay was killed by the memory watcher. Lead policy since then: workers = all 14 hosts, at most 2 heads per agent, on your own hosts.
7. **31's target folded into its enclosing region.** The throw at RSRpcServices:1880 is in throwOnWrongStartCode(long) (REGION.208b3b8c), but that region folds into the enclosing throwOnWrongStartCode(ExecuteProceduresRequest) (REGION.4a0683a9), and the recording observes only the latter. A selector on 208b3b8c gives DECLARED_TARGET_OCCURRENCE_UNOBSERVED (R19SEL-31). Pick the selector from the observed-occurrences list in that error. A region server started inside the window is the next `rsN` (the restarted rs0 became rs3).
8. **Static demand at writer guards** (df030a4e2, merged). PLAN moves a writer only if its guard reaches a tracked cell, so RootDemand now walks again from the guards of the chosen tracked fields' writers (measured WRITERS). Before this, ns-rsgroup's removeRSGroup was a "fixed decider".
9. **Claim-loop model** (2936a75db, merged). campaign_claim_model keeps only the selected path's arms (by the `__N__` ordinal). Before, arms of other paths leaked into the refuted model (H4's 22).
