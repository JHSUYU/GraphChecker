## 6. Running a case (any branch, liftlab)

1. A snapshot of the branch: `GC_REPO=~/GraphChecker bash tools/lib/worktree-add.sh /u/vnr3ne/gc-run/<name> <commit>
   --detach`, then `cd` there and `mvn -q -o package -DskipTests` on a Maven host.
2. The trees: `GC_TREES=<tree set> GC_M2=<maven repository> bash experiments/<sys>/prepare-trees.sh [tree...]` on a
   Maven host (clones each tree's fork branch from GitHub, builds it, runs every workload natively once; a few
   minutes per tree; several hosts at once).
3. One or several cases at once, from lift11: `env GC_OUT=<dir> GC_TREES=<tree set> GC_M2=<maven repository>
   LIFTS="<workers>" CAUSYNTH_CUSTOM_JDK_HOME=<vm image>/j2sdk-image CASE_TIMEOUT_SECONDS=21600 PRUNE=0
   CASES="<case> ..." bash <snapshot>/tools/rounds/launch-round.sh <snapshot> <ROUND>` (each case gets a head where
   memory has room; the ledger spreads every replay over the workers); the run is
   `<GC_OUT>/accept-<ROUND>-<case>` (`hdfs-` dropped). B1's own launcher:
   `/bigtemp/vnr3ne/analysis/buggy-detect-liftlab-2026-10-28/launch-b1.sh <system> <case...>`.
4. Read: `summary.tsv` (claim, report.py's verdict), `out/<case>/schedule/final/{confirm,reproduce}.json`,
   `tools/analysis/vacuity.py` for an UNSAT, `tools/analysis/smt-legend.py` for the formula; a buggy-detect branch's
   `results/<sys>-buggy/final-stats.py --cases experiments/<sys>/<sys>-buggy-cases.tsv` makes its table.
