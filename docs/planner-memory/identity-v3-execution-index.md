Owner: the core challenge is cross-replay occurrence correspondence under branch flips; borrow Execution Indexing (PLDI'08) / PEPID (ASE'13) for the local index and distributed tracing's parent-span STRUCTURE (not random ids) for the causal context. OccurrenceId = TopologyEpoch + LogicalComponent + StaticRegionId + CausalContext + LocalExecutionIndex; consumer identity = region + incoming causal anchor (producer occurrence + RPC static site + producer local index) + consumer local index. Case declarations stay human selectors (v1 spelling) resolved against the seed.

**Why:** flat ordinals shift when an unrelated invocation is inserted; random span ids differ per replay; only structural context + causal anchor is stable.
**How to apply:** contract v2.0 (OccurrenceAddress with CausalContext + ExecutionIndex; Endpoint with a site-local index), runtime computes from the invocation tree + loop counters + the starting attach; explore/compose use ids only. See [[graphchecker-core-design-principle]], [[lineage-identity-idea]], [[graphchecker-refactor-goal]].

**Pass-equality rule (2026-09-15, learned over G2–G5):** the identity is one function AND one input set in both passes. Inputs of OccurrenceAddress/Endpoint that must be fed identically by the SEED recording and every replay: node attribution (receiver source + start-frame inheritance), region frame set (every skeleton root opens a frame in BOTH passes — the campaign's rich hooks and lite hooks never both on one method), thread-start frames, call-site iteration frames (frame journal), loop-root invocation frames and any loop iteration charge (a replay-only hook such as checkLoopBackedge→Identity.loopIteration must not feed the address), accessor-call-context frames (replay-only → deleted), producer endpoint (occurrence, transport site, k-th event at that site in that occurrence), read/write endpoint siteIndex (k-th event at the site in the occurrence). Any new hook that pushes a frame or counts an event must be woven in both passes or in neither. Gate: SEED 0 unexplained collisions, replay planned==ran for every answered task, IMPORT gate 0 violations, wave 0 obligations unchanged.

**LOV extension (idea, 2026-09-15, discussed with the owner over Sumner & Zhang ASE'13):** our index is PEPID-shaped (calling context + per-loop iteration counts + site, plus causal anchor and node). PEPID aligns iteration k with iteration k, so a replay that executes one iteration more or fewer than the recording shifts every later address — refused fail-closed, by design. The one design-consistent way to align such loops is STAT's loop-order variable: a case DECLARES, for one retained loop, a monotone per-iteration variable (e.g. the edit-log txid in `applyEditLogOp`) that replaces that loop's iteration count in the index, fed identically in both passes. Contingent: only if a case's structural nondeterminism cannot be pinned by config (so far every candidate — the 17960 −1 shift — turned out to be an engine defect). Never a heuristic match.
