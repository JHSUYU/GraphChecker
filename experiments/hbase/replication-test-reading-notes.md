## New candidate under verification

An old-format peer lacks its `new-sync-rep-state` child. Master startup repairs only current sync state, leaving the missing new child. A RegionServer startup reads config and current state before `getPeerNewSyncReplicationState`. That method reads a missing child, then checks parent existence. If Master `removePeer` deletes the peer after that check, the RegionServer calls `ZKUtil.createSetData`; its `createWithParents` recursively recreates the peer parent with zero-length data. `listPeerIds` then includes the ghost ID, and `getPeerConfig` explicitly throws `ReplicationException("Replication peer config data shouldn't be empty, peerId=...")` under `if (data == null || data.length == 0)`. The existing old-format test covers lazy repair without deletion. The new mini ZooKeeper regression confirms the storage-level path. No exact prior found in targeted ASF Jira searches; novelty remains provisional.
