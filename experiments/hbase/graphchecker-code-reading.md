## Implementation path established from source

1. **Seed predicate.** `annotation/CausynthExceptionTarget.java` marks a `new` expression as a class-file type-use annotation; `causynth/ExceptionTargetAnnotationScanner.java` scans application `.class` files with ASM and requires exactly one matching `NEW`. `CausynthTargetResolver.java` gets `exception_target_id` from a small target YAML and the output path from JVM properties. `GraphCheckerMain.java` configures Soot with production outputs as application classes and test outputs as classpath only. `CausynthPipeline.java:136-204` runs the seed backward analyzer, plans skeletons and symbolic sources, creates the static scope map **before weaving**, and writes discovery artifacts. The rest of `CausynthPipeline.java` and most of `SeedBackwardStaticAnalyzer.java` remain unread semantically.
2. **Local records.** `run_engine.sh:680-746` drives two stock-JVM recordings: lite activation skeletons, then rich region-state traces over selected methods. `ImportGateMain.java` checks session row invariants before exploration and appends named blocking or diagnostic gaps. The custom VM broker and runtime recorder were sampled, not exhaustively read. The README says the VM's shadow expressions propagate values inside each JVM; the static graph scopes instrumented regions rather than constructing symbolic provenance itself.
3. **Counterfactual branches.** `ExploreMain.java` reads all sessions of one epoch, resolves one declared target occurrence, computes a closure, reconciles interaction slots, and offers fresh obligations. `ClosurePlanner.java` starts with the target's guard set and grows through demanded read/write and wire rows plus static candidate write/export sites. `ObligationFactory.java` defines one obligation as a recorded path prefix with one decision negated. `FocusedReplay.java` makes the selected occurrence, its state-connected factor, and relevant root-mint occurrences symbolic; others run concretely. `FlipQuery.java` constructs the counterfactual SMT question, closes its variables over reachable expression leaves, and refuses unstated names and incompatible state shapes.
4. **Cross-component composition.** `Composer.java`, `ComposedFamilies.java`, `ComposeMain.java`, `ClaimPolicy.java`, `Z3.java`, and all 12 Java tests are FULL. The composer disjoins admitted paths, binds each read to its observed version or an attested alternative, and refuses paths with unsupported or unstated terms. `SmtLowering.java` is FULL: its leaf registry distinguishes recorded declarations from execution-local identities; its session join resolves observed write versions or mint versions; it names container DAGs and propagates definedness. Wire attaches and state reads receive families of attested alternatives; their selectors bind incoming variables to producer expressions and conditions. `ContainerSmtCodec.java` lowers indexed and associative state into SMT, projecting scalar observations through recorded choice wrappers and requiring definedness for positional operations. ClaimPolicy rejects solver errors, requires an unsat core at the recorded valuation to name a valuation assertion for root-move polarity, and distinguishes one inert path (diagnostic) from **all** paths inert (blocking). `RowInvariants.java` checks session contracts and valuations at import.
5. **Dynamics closure and limits.** `run_engine.sh:2927-3056` iterates topology epochs when a replay reports `TOPOLOGY_DIVERGENCE`. The default shell bound is three epochs; `ClosurePlanner.DEFAULT_MAX_TASKS` is 64, with truncation named as blocking. `ObligationFactory` has per-task path and flip bounds. These make the implementation a bounded exploration; reaching a limit is not a proof of global closure. The paper's general dynamics-closure claim must be interpreted through the concrete admission and gap artifacts.

The current code's `GapKind.PATH_SELF_CONTRADICTORY` enum comment says blocking in broad terms, while `ClaimPolicy.java:431-466` and `README.md:298` implement diagnostic per inert path and blocking only when every disjunct is inert. This is a documentation mismatch, not evidence that the algorithm itself is wrong.

### Duplicate seed target probe

`Composer.admit()` iterates every target row at the anchor and adds its session's path each time. A real Composer fixture with two reached target rows in one seed session and one explored session produced three disjuncts. Each seed selector forced alone was `sat`, while forcing both was `unsat` solely because `target_path_partition` asserts exactly one selector. `ClaimPolicy.seedDisjunctUnsat()` forces all seed selectors together, so that method reports `unsat` under this input even though both seed paths are individually satisfiable. In the actual `ClaimPolicy.decide()` run, the two seed rows share the same `(session, occurrence)` path ID, so its forced assertions also duplicate the `:named seed_disjunct__...` label. Z3 reports `named expression already defined`, and `decide()` returns `NO_SUPPORTED_WITNESS` with a blocking solver-error gap. The probe additionally raised `FORMULA_SAT_AT_RECORDED_VALUATION` as blocking. Thus the test demonstrates a bad intermediate seed-refutation check and poor diagnosis of duplicate target rows, **not** a publishable false finding from this corpus. No production HBase finding follows from it. The probe used a temporary copy of `ComposerTest` outside the repo and left no main/test source modification.

`RowInvariants.onePerEvent()` blocks duplicate targets only when `(seq, anchorSiteId)` repeats. Multiple target rows at the same anchor and occurrence with different sequence numbers pass this gate, so this input shape is not excluded by import validation.

### State and topology model boundaries

`Arms.stateArms()` selects each writer occurrence's **last** write to a location. `ComposedFamilies` and `FlipQuery` then share one writer choice among all reads of that location in a reader occurrence; the comments explicitly disallow a writer interposing between those reads. This can omit HBase executions where a cache update occurs between two reads in one occurrence. It can also exclude a recorded read of an earlier write from a writer occurrence that later writes the same location again. This is a model coverage limit to check when designing HBase seeds, not proof of a HBase bug.

`Frontier` identifies an owed flip by task/occurrence, branch site, ordinal, and flipped outcome, without its path prefix. Once any session records that outcome, or a wave returns ADMITTED, UNSAT, or NOT_ADMITTED, the frontier does not retry that branch under another prefix. Thus branch combinations within one occurrence can be omitted, even though the composer may combine distinct recorded paths and producer arms. A closed frontier is closure under this arm key, not all possible path combinations.

`Arms.concurrent()` recognizes same-thread order and followable message-anchor chains. The current `ActivationRow` contract contains no thread-start/join edge, so those causal relations are not represented by this comparator. Chains it cannot follow are treated as nonconcurrent. `SlotTable` comments still claim thread start/join coverage, contrary to the `Arms` implementation and its explicit comment. Consequently, an HBase witness depending on thread lifecycle ordering requires independent schedule validation.

`ContainerSmtCodec` supports a specified subset of indexed and associative operations. It refuses indexed `CONTAINS`, unknown field projection, and an associative read whose mutation chain lacks a stated base. Its scalar projections preserve observed-version and boundary wrappers; large unknown-size indexed shifts defer to a quantified definition and carry an unsupported marker. These constraints can leave a HBase predicate unproved even if a concrete schedule exists.

`VmLoweringCore.stringIdentity()` encodes Java reference `==`/`!=` against a String literal as content equality when the other term has a nullness bit. That is not valid for a non-interned string: `new String("x") == "x"` is false although the contents match. The lowering checks neither an interned property nor an allocation identity for that other term. A candidate involving this comparison can receive an incorrect branch condition; an independent Java replay is necessary before accepting such a witness. This is a GraphChecker model risk, not a HBase finding.

`SmtNames.rename()` omits unknown-symbol detection for any entire term containing `(let `, including names outside that binder. Final composition also runs `Composer.unknown()` over terms and excludes any path with a named unknown; if an undeclared constant survives, a Z3 parser error is blocking in `ClaimPolicy`. Conversely, `Composer.unknown()` does not understand `let` scopes and may treat a legitimate bound variable as unknown, excluding a valid path. This is a completeness and diagnostic risk pending a whole-pipeline probe, rather than a demonstrated false witness. `SmtNames` tokenizes string literals and quoted names with a simple closing-delimiter scan, so unusual escaped literals merit verification if they appear in a HBase predicate.

## Shortest HBase integration route

The present HBase checkout has **no** `@CausynthExceptionTarget` or GraphChecker runtime hooks (search over its Java source). Its root `pom.xml:865` sets `releaseTarget=17`, whereas GraphChecker's POM targets Java 8 and the README and Hadoop `execute.sh` route focused replay through a customized OpenJDK 8 Zero VM. The configured `third_party/OpenJDK-Concolic-Execution-Engine/build/.../j2sdk-image` is absent in this workspace. This blocks a current full HBase concolic campaign without porting that VM or another Java 17 propagation backend. It does not establish that the static Soot seed cannot read Java 17 classes; that has not been tested.

A concrete first HBase case should use an already isolated, explicit production `if (...) throw new ...` site, with the `@CausynthExceptionTarget("hbase-case-id")` type-use marker on that `new`. The target method must be in the **production** output processed by Soot; the JUnit workload is placed only on the classpath. Supply `target.yaml`, `workflow.properties`, a healthy JUnit test adapter, `symbolic-inputs.jsonl` naming the relevant cached/control-plane state or clock, `loop-bounds.jsonl`, and `communication-mappings.jsonl` if producer and consumer communicate over RPC. `run_engine.sh:435-496` lists the required workflow values; `:496-680` passes declarations into static analysis; `:1514-1604` defines the seed stage. HDFS-11741's mapping file is a concrete wire-flow schema example, but its HDFS signatures cannot be reused for HBase. The campaign must name one observed target occurrence, not only an exception class.

For a shorter, immediately executable route on this checkout, the HBase team has already used **production-code regression tests plus explicit SMT** over the control-plane/data-plane state relationship. That gives evidence for the requested bugs without claiming GraphChecker itself executed a HBase case. Running a full GraphChecker campaign also requires a separate unit test to confirm any candidate, since `README.md` explicitly states that `candidate.smt2` and solver verdicts are its deliverable and it performs no confirmation replay.
