# HBase Java test workload reading

The [per-file index](hbase-test-reading-index.tsv) lists 2,659 Java files under HBase `src/test/java` trees across 29 modules. Path, line count, and SHA-256 are a machine inventory; `semantic_status=full` is set only after the named file has been read in full and its scenario recorded here. Files marked `partial` or `inventory_only` have **not** been semantically reviewed end to end. The root [whole-source inventory](/u/vnr3ne/coordination-audit/source_inventory.jsonl.gz) also remains a byte index, not a reading claim. This index excludes non-Java test resources and integration scripts.

## hbase-replication: 7 of 7 Java test/support files read

- `ReplicationPeerStorageTestBase.java`: shared FS/ZK storage contract adds ten peers with alternating enabled flags and four sync states, checks configs, updates, state changes and removal, expects `ReplicationException` for a removed or nonexistent peer, repairs a missing old-format sync-state node, and rejects duplicate peer IDs. It has no crash between storage substeps.
- `TestFSReplicationPeerStorage.java`: runs that shared contract on a local filesystem, deletes the rotated sync-state file to exercise old-format repair, and checks duplicate ID text. It does not cover an orphan `disabled` marker after partial `removePeer`, the separate resurrection finding.
- `TestZKReplicationPeerStorage.java`: runs the same contract against a mini ZooKeeper cluster, deletes both old/current sync-state znodes for repair, and expects `NodeExistsException` beneath a duplicate-ID error.
- `TestReplicationStateBasic.java`: shared ReplicationPeers contract rejects bogus IDs, adds/removes/readds peers, checks config-derived cluster key, and manually refreshes a peer after enabled state toggles. Its assertion waits for local peer state to match storage, but it never injects divergent Master/RegionServer storage views.
- `TestReplicationStateZKImpl.java`: supplies mini ZooKeeper and two synthetic peer-cluster znodes for the basic state contract, creates a fresh ReplicationPeers instance per test, and clears replication znodes after each test.
- `TestCopyReplicationPeers.java`: migrates ten peer records from ZooKeeper to filesystem storage and verifies the destination IDs/configs; it also checks invalid CLI arguments. It does not interrupt migration or compare enabled/sync state after migration.
- `TestZKReplicationQueueStorage.java`: builds legacy ZooKeeper queue, last-pushed-sequence, and HFile-ref trees; migration iterators decode normal/recovered queues and delete consumed znodes, including empty intermediate branches. The test verifies record counts, WAL offsets, peer IDs, sequence IDs, HFile refs, and eventual subtree deletion.

## Additional backup and replication paths excluded after full source review

- `TestSerialReplicationChecker.java`: all 303 lines read.
