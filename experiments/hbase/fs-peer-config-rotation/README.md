# FS peer config rotation during a RegionServer read

`RotateFile.read` checks slot 0 and then slot 1 (`hbase-client/.../RotateFile.java:114-131`). `RotateFile.write` writes the next slot and deletes the previous one (`:162-176`). If only slot 1 exists, the RegionServer reader can miss slot 0, then a Master update writes slot 0 and deletes slot 1, and the reader misses slot 1. Each instant has a valid config; the two observations do not belong to one instant. `FSReplicationPeerStorage.getPeerConfig` receives null and its `if (data == null || data.length == 0)` throws `ReplicationException` (`hbase-replication/.../FSReplicationPeerStorage.java:218`). `Replication.initialize` wraps this in `IOException: Failed replication handler create` (`hbase-server/.../Replication.java:105-107`).

The [green unit test](/u/vnr3ne/hbase/hbase-server/src/test/java/org/apache/hadoop/hbase/replication/regionserver/TestFSPeerConfigRotationDuringReplicationInit.java:111) uses real filesystem peer storage and `Replication.initialize`, a pausing `FilterFileSystem`, and a mocked `Server`. Its [Surefire report](/u/vnr3ne/hbase/hbase-server/target/surefire-reports/org.apache.hadoop.hbase.replication.regionserver.TestFSPeerConfigRotationDuringReplicationInit.txt) says 1 test, 0 failures, 0 errors. It verifies the initial slot-1 config, the successful final slot-0 config, the wrapped exception, and the intact peer after failure. It does not start a complete RegionServer or use a remote filesystem. The [hand SMT model](/u/vnr3ne/hbase/hbase-server/src/test/resources/adhoc-coordination/fs-peer-config-rotation-read-race.smt2) returns `sat` for the split read and `unsat` for reads entirely before or after rotation; it is a source-state abstraction, not GraphChecker bytecode execution.

Targeted Jira/GitHub searches found no exact predecessor. [HBASE-27110](https://issues.apache.org/jira/browse/HBASE-27110) introduced the optional filesystem storage; [the HBase guide](https://hbase.apache.org/docs/operational-management/cluster-replication/) describes the two-file representation. Novelty is provisional. This case differs from peer removal during initialization because no peer or config is actually removed from the store as a whole.
