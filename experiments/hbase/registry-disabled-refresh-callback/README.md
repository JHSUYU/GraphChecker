# Disabled registry refresh fails a connection-error callback

`RegistryEndpointsRefresher.create` returns null for a negative periodic refresh interval (`RegistryEndpointsRefresher.java:141-152`). `AbstractRpcBasedConnectionRegistry` stores that nullable refresher (`:92-95`). When a Master registry RPC reports a connection error, its callback first completes the request future exceptionally, then takes `if (ClientExceptionsUtil.isConnectionException(failureReason))` and calls `registryEndpointRefresher.refreshNow()` without checking for null (`:124-132`). The result is a `NullPointerException` escaping the callback after the public future has failed with `MasterRegistryFetchException`. The same class checks for null when it closes the registry (`:254-257`).

The targeted test `hbase-client/src/test/java/org/apache/hadoop/hbase/client/TestDisabledRegistryRefreshConnectionFailure.java` uses a real `RpcConnectionRegistry` and its public `getMetaRegionLocations()` call. It injects a controlled `ClientMetaService` stub into the registry's stub holder to supply a `ConnectException`, dispatches the real RPC callback on a separate thread, and captures its uncaught exception. It checks the original public future failure, the callback-thread NPE and stack frame, then deliberately fails a final safety assertion. A positive refresh interval is a healthy control. This test does not use a real network endpoint; the behavior of a transport's exception handler and any log message remain untested. `RpcConnectionRegistry` is the current bootstrap-based registry; the deprecated `MasterRegistry` inherits the same callback implementation but is not the test subject.

The targeted Maven run `/tmp/hbase-disabled-rpc-registry-refresh-async-test.log` reports 2 tests, 1 deliberate final safety failure and 0 errors. Its Surefire report is `hbase-client/target/surefire-reports/org.apache.hadoop.hbase.client.TestDisabledRegistryRefreshConnectionFailure.txt`. All preceding assertions, including the public future exception, callback-thread NPE type and stack origin, and healthy control, pass. The earlier synchronous-stub trial in `/tmp/hbase-disabled-registry-refresh-test.log` is superseded by this asynchronous run.

The hand-built SMT file is `hbase-client/src/test/resources/adhoc-coordination/disabled-registry-refresh-connection-failure.smt2`. Z3 yields `sat/unsat/unsat` for disabled refresh plus a connection error, enabled refresh control, and no connection error control. The model is a source-derived state abstraction, not end-to-end symbolic execution of HBase bytecode; the Java test is the implementation evidence.

Existing `TestRegistryEndpointsRefresher` tests disabled construction and scheduling without a registry RPC failure. `TestMasterRegistry` tests endpoint changes and failure handling with refresh enabled. `TestRpcBasedRegistryHedgedReads` tests failed/valid replies without disabling refresh. Targeted ASF Jira and apache/hbase searches on 2026-09-19 for the exact refresher method, null refresh interval, and connection-error callback found no matching issue. [HBASE-26150](https://issues.apache.org/jira/browse/HBASE-26150) introduced `RpcConnectionRegistry` and its error-triggered endpoint refresh; it does not report this disabled-refresher NPE. Novelty remains provisional.
