# MOB TTL cleaner using a stale minVersions descriptor

`MobFileCleanerChore.chore` reads all table descriptors and submits one asynchronous task per captured descriptor (`MobFileCleanerChore.java:109-122`). `handleOneTable` selects the TTL cleaner if that captured family has `minVersions == 0` (`:152-156`). The task does not reload the descriptor after a concurrent `Admin.modifyTable` completes. `MobUtils.cleanExpiredMobFiles` uses the captured TTL and MOB filename date to archive old files (`MobUtils.java:279-355`).

A region with `minVersions=1` must retain its last version despite TTL. `StoreScanner.java:483-485` explicitly disables whole-HFile TTL exclusion in this case. Thus a public `Get` can still need a MOB value that the stale cleaner considers expired. After normal archive TTL deletion, `HMobStore.java:439-446` takes the missing-file branch and throws `DoNotRetryIOException`.

The [mini-cluster test](/u/vnr3ne/hbase/hbase-server/src/test/java/org/apache/hadoop/hbase/mob/TestExpiredMobFileCleanerMinVersionsRace.java) flushes an old MOB value while TTL is unlimited, then uses public `modifyTable` to establish a one-day TTL/minVersions=0 descriptor and captures it. A second public `modifyTable` sets minVersions=1. A public `Get` reads the value before cleanup. The test resumes the production `ExpiredMobFileCleaner` with the captured descriptor, verifies archive and HFile cleaner deletion, and observes the exact public `Get` exception.
