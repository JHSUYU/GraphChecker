## Exception and coordination assessment

- `RSGroupInfoManagerImpl.removeRSGroup` checks server count, table descriptor references, namespace references, then deletes the group. The legacy tests (`TestRSGroupsAdmin1`) cover static references, but do not interleave a table or namespace procedure with the scan. Namespace creation after prevalidation and removal before INSERT is already counted as `HBASE-NAMESPACE-RSGROUP-REMOVE-RACE-001`; the analogous table-descriptor version shares the validation-versus-removal root and is not offered as a distinct finding.
- `TestRSGroupsAdmin2` deliberately changes a `RegionStateNode` to SPLITTING to force a move failure, then repairs and retries. This covers the existing retry-exhaustion exception; a real independent state transition causing a new exception path was not established from this workload.
- `TestRSGroupsOfflineMode` demonstrates that the Master can be initialized while `RSGroupInfoManagerImpl.isOnline()` is false and that the balancer uses ZooKeeper for a group table outage. `flushConfig` explicitly forbids nondefault-group changes in offline mode (`RSGroupInfoManagerImpl.java:643-679`); that is its documented mode restriction, so no new bug is inferred merely from that exception.
- `TestMigrateRSGroupInfo` verifies group lookup before and after the background migration. A conflict between migration and a concurrent rename/removal would need a concrete uncaught condition downstream; the file does not itself demonstrate one. No new finding is asserted.
- Existing targeted files in this directory already cover committed ZooKeeper multi plus lost ACK on remove, persisted rename versus stale table/namespace references, failed group-table write versus in-memory holder, and a detached multi-table descriptor callback. They must not be recounted from these full reads.
- This pass found no additional, sufficiently demonstrated cross-component state relation ending in a new explicit exception branch. No Maven run was needed.
