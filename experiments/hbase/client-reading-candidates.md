## Rejected or unverified candidates

1. **Sparse Meta znode indexes.** During a change from one to three Meta replicas, `ModifyTableProcedure.assignNewReplicasIfNeeded` submits independent child assignments for replicas 1 and 2. `RegionStateStore.updateRegionLocation` mirrors each successful state to ZooKeeper separately. Therefore the base znode children can temporarily contain the default and replica 2 while replica 1 has not published yet. `ZKConnectionRegistry.getMetaRegionLocation` sizes `locs` by the number of znode children, then indexes it by numeric replica ID; `{0,2}` gives length 2 and index 2. This is an `ArrayIndexOutOfBoundsException` in a callback, likely leaving the returned future incomplete. **Do not count it as new:** the ASF Jira [HBASE-25280](https://issues.apache.org/jira/browse/HBASE-25280) is explicitly titled “ArrayIndexOutOfBoundsException in ZKConnectionRegistry.” No new test was written for this already reported problem.
2. **Near-prefix Meta znode names.** `ZNodePaths.isMetaZNodePrefix` accepts any child starting with the Meta prefix; a child such as `meta-region-server-backup` passes the list filter, and `getMetaReplicaIdFromZNode` would throw `NumberFormatException` parsing `backup`. Existing `TestZNodePaths` does not test this collision. No production writer of such a child was established, so this is only an unverified configuration or external-znode hypothesis. The failure also belongs to the same registry path as HBASE-25280 and should not be presented as a fresh finding without a concrete production trigger and novelty check.
3. **RotateFile checksum recovery.** `TestRotateFile.testChecksumMismatch` already asserts that a corrupted readable file makes `RotateFile.read` throw `IOException`, even if the other rotation slot may contain an older version. This is current documented/tested behavior, and a single persistence object rather than the requested control-plane/data-plane relationship.
4. **SASL QOP mismatch.** `TestSaslUtil` expects `verifyNegotiatedQop` to throw `IOException` on weaker negotiated protection. This is an intentional security rejection rather than a coordination bug. Several duplicated assertion values in that test appear to be test typos, but provide no new runtime bug evidence.

The assigned tests mostly cover static configuration conversion, serialization, mock RPC priority/tracing, and isolated utility behavior. They do not collectively exercise live Meta znode transitions, live replication peer propagation, or mixed client/server failure windows. No new finding was registered from these files.
